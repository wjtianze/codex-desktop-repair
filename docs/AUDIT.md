# 排查范围与修复依据

## 已确认并修复

主进程与界面进程都曾为短标题解析整段历史预览。主进程还会提前计算未被采用的候选标题。实际处理器采样把主要阻塞定位到这条调用链。现在采用已有名称优先、预览解析上限与有限缓存；完整正文仍由正常渲染流程处理。

其他确认项包括性能采样记录累积、空监听表残留、未落实的闲置历史容量目标、浏览器整文件读取和通知排队、可选设备初始化失败后的清理异常、连续渲染器崩溃恢复循环，以及窗口恢复的异常尺寸。相关保护均使用原版本提取的方法或合成边界数据进行测试。

输入框问题在实际客户端复现：私有对话已经有本地状态，但相应查询缓存了 404，导致输入框被卸载。对同一个查询做只读重取后，输入框立即恢复。补丁保留这种短暂状态下的输入框，进行有限重试；仍遵守原有提交和访问检查。用户已确认恢复正常。网页版短暂消失来自用户观察，未直接确认其内部根因。

## 1.0.1 追加审阅

本轮对主进程保存与日志、历史和消息转换、图片布局、引用卡片、对话模型选择、草稿与提及搜索作了针对性审阅。资源清单扫描覆盖整包；不把第三方依赖的关键词扫描描述为逐行审计，也不将未复现的公开反馈列为已修复。

- 单张竖图的重建宽度可能得到 400.00000000000006，严格比较错误地进入正方形裁切分支。现在优先保留单图原始比例，并容忍浮点舍入误差。用户已确认完整显示。
- 文件检索返回的内部页面图片被误当作生成图集。现在根据工具角色和来源识别；用户上传和生成图片仍正常显示。
- 文件引用按来源和展示意图区分，覆盖不同扩展名。预览迭代中曾出现局部变量提前访问导致的 Markdown 异常，已回退并修复；回归直接执行完整引用组件，覆盖紧凑引用、下载文件、限制状态和无侧栏版本。用户已确认卡片和渲染恢复。
- 模型与思考档位按会话保存，草稿标识转换为正式会话标识时迁移偏好。缺省档位取真实可用槽位，避免标签和滑块不一致。只保存选择字段。
- 弱引用缓存复用未变化的历史转换和元数据；流式状态、分支、正文映射、审核提示和遥测依赖变化时重新计算。普通聊天跳过未使用的工作摘要。用户已确认生成内容不再消失。
- 原生日志队列在持续背压下保留已写出的记录。复现中已消费 3001 条、待处理 0 条，数组仍保留 3001 条。修复后立即释放已消费数据；积压按 8 MiB 限制，超长单条记录保留首尾并注明截断，防止无界增长。未据此断言所有内存增长均来自日志。
- 状态保存队列把突发的重复写入合并为一轮；写入进行中仍允许排一轮最新状态。普通刷新等待异步写盘，严格保存保留原有错误契约。原生主文件、备份、临时文件替换和读取格式均保留。

- 首次安装曾错误使用 MSIX 包的虚拟化缓存资料目录。当前受支持包明确声明 FileSystemWriteVirtualization 为 disabled，修复版默认改为官方实际使用的 Roaming\Codex；升级保留已有绝对路径。此项避免进入空资料目录，不迁移或删除账号文件。

- 快速聊天的快捷键注册与新聊天行右侧按钮，共用一个额外要求 Codex 模式的条件。移除该模式限制后，ChatGPT 模式复用同一个按钮、快捷键处理及浮窗；功能可用性和显式禁用条件仍保留。

## 1.0.2：项目设置与工作过程显示

核对日期：2026-09-08，官方商店版本未改变。

项目资料上传和删除本来就通过独立接口即时保存，但项目设置弹窗的可保存条件只计算名称、图标、颜色和指令。文件变更成功后，界面仍显示未修改。新增的变更跟踪只在操作成功后计入修改，所有文件操作完成前禁用保存；失败继续走原有提示。原生保存函数已会忽略未变化的项目字段，因此只改文件不会重复提交改名或覆盖项目数据。并发删除、保存重入、权限和无效名称也有对应验证。

工作对话的 Zm 适配器把所有 reasoning 条目都转换成 assistant-message/commentary，还会把它们与前面的进度说明拼接，遗漏了 thought 与 preamble 的区别。现在只有明确的 preamble 保留为普通进度说明，真正的思考摘要继续以 reasoning 进入原生折叠组件。原生 CLI 中的灰色摘要和底部状态提示不能仅凭文字相同就认定为重复消息，本版未修改 CLI 或隐藏其事件。

同一个工作过程还会保留全部 todo-list 更新，导致第 2/3 步与第 3/3 步并排出现。视图现在只保留该组最后一份计划快照；其他活动顺序、原始消息数据和不同轮次的独立计划均保留。

这两条显示路径在原始官方资源中即可确认，与此前新增的渲染缓存无关。新增 30 项行为验证，包括 6 项独立变更跟踪、12 项完整项目设置组件和原生保存函数验证，以及 12 项工作活动适配验证。

### Chat 流式摘要

Chat 的 Ym 视图在生成开始时以空内容挂载原生摘要组件 g_。g_ 的初始展开状态由 canExpand 决定，后续内容出现并不会重置 React 状态；因此从空摘要起步的流式摘要始终收起。视图现在在第一段可展开内容到达时更换一次活动组件键，后续文字更新沿用同一个键，以保留用户手动收起的选择。原生完成摘要、Work 路由和服务端 hide_all 指令保持原有行为。8 项测试实际执行原生 Ym 与 g_ 的状态切换。服务端未发出内容时，客户端无法自行补出实时摘要。

### 快速聊天消息操作

快速聊天使用的精简 transcript 将 onEditUserMessage 设为 undefined，且未转发 onRegenerateResponse，所以消息菜单缺少两项入口。现在仅由快速聊天显式启用消息操作，其他预览保留原有行为。编辑按需调用主聊天页面的原生 Ms；重新生成调用原生 response 模块，保留模型、搜索和反馈选项。不另造发送协议，也不改写既有消息存储。

操作期间禁止重复调用；切换会话使旧回调失效；生成中、缺少服务端会话、Work、只读、归档和功能限制状态不提供操作。原生编辑仍校验活动分支、定向回复、空文本和附件，保留父节点、附件、模型与思考档位。8 项独立操作测试和 8 项完整精简视图/原生编辑测试均通过。未以真实账号请求生成进行验收。
